# 给店主的一页说明：会员系统上线

会员功能（糖豆人会员）的代码已经写好并在测试库验证过了。线上环境只需要做**一件事**：执行一次数据库迁移。

---

## 你要做的

**1.** 登录你们的 Supabase 项目，左侧菜单点 **SQL Editor**，再点 **New query**

**2.** 打开仓库里的 `docs/上线迁移-一次执行.sql`，把**全部内容**复制粘贴到那个编辑框里

**3.** 按 **Run**（快捷键 `Cmd+Enter`）

会弹一个提醒框，写着 `Potential issue detected / destructive operations`。这是正常的，先点 **Run query** 继续。
（它删的是几样「先删再建」的东西：旧的 5 参数版结算函数、旧版（如果有）的 VIP 月卡表与两个函数、旧版「发券」奖励表 `member_rewards` 与 `ensure_member_rewards` 函数、以及新表上刚建的约束。**不会碰任何现有数据**。）

**4.** 看到绿色的 `Success. No rows returned` 就完成了

整个过程不到一分钟。这个脚本**可以重复执行**，万一中途出错，改完再跑一次不会出问题。

---

## 这个迁移做了什么

| 动作 | 内容 |
| --- | --- |
| 建 1 张表 | `members`（会员身份：邮箱、姓名、加入时间、同意来源） |
| 给 1 张表加 3 列 | `timer_sessions` 加 `member_id`（这单属于哪位会员）、`reward_eligible`（是否计入奖励进度）、`discount_source_snapshot`（这一单享了哪种优惠） |
| 建 1 个视图 | `member_visit_days`（按伦敦自然日算到店次数，同一天来多次只算一次） |
| 建 3 个函数 | `settle_timer_session`、`unsettle_timer_session`、`link_timer_session_to_member` |
| 升级 1 个函数 | `settle_timer_session` 从 5 个参数扩到 8 个，**老调用方式照旧可用**，不影响现有的计时结算 |
| 删旧版奖励 | `member_rewards` 表与 `ensure_member_rewards()` 函数（旧版「发券、稍后核销」机制，已废弃） |

**不删现有业务数据。** 脚本里那句 `DROP FUNCTION` / `DROP TABLE` 只删旧版签名与旧版奖励对象（新版已不再使用），`DROP CONSTRAINT` 只删刚落的新表上的约束。生产库在本迁移前还没有会员数据，所以都是空操作或「先删再建」。

---

## 迁移之前 vs 之后

| 阶段 | 表现 |
| --- | --- |
| 迁移前 | 会员页面能打开，但提交时提示「查询失败，请重试」。**计时、预约、结算、优惠券全部照常**，不受影响 |
| 迁移后 | 会员功能完整可用：注册、到店计数、达标自动打折、结算折扣 |

所以这个迁移不存在「必须停机」的问题，找店里不忙的时候跑就行。

## 想复验（可选）

仓库里有一份验收脚本 `docs/verify_via_api.py`，覆盖 29 项规则（到店计数与同日去重、3/5/7/10 次那单自动打折、四档金额逐一核对、每 10 次一轮、同一天第二笔原价、券码冲突被拒、折扣只能用在本人订单上等等）。

在**有该项目 service key 的机器上**，把它放在仓库根目录跑：

```bash
python3 verify_via_api.py
```

应输出 `通过 29/29`。这个脚本会读写几笔测试数据，跑完会留下三位测试会员（`demo.a@` / `demo.b@` / `demo.c@tangdouren.test`），可以手工删掉。

## 会员奖励：怎么算折扣（2026-10 二次改版：达标自动打折）

到店次数按「自然日」算，同一天来多次只算一次。**不存券**；客人达到相应次数的那一单自动打折，其余次数原价：

| 到店次数 | 那一单自动享 | 举例（原价 £13.99） |
| --- | --- | --- |
| 第 3 次 | **9 折**（减 10%） | £13.99 → £12.59 |
| 第 5 次 | **8 折**（减 20%） | £13.99 → £11.19 |
| 第 7 次 | **7 折**（减 30%） | £13.99 → £9.79 |
| 第 10 次 | **5 折**（减 50%） | £13.99 → £6.99 |

几条规矩：

| 情况 | 规则 |
| --- | --- |
| 折扣什么时候给 | **到店次数达到 3/5/7/10 次的那一单自动打折**，不用领券、不用店员手动选 |
| 到了第 10 次之后呢 | **每 10 次一轮**。第 13 / 15 / 17 / 20 次继续自动给 9 / 8 / 7 / 5 折，一直循环下去 |
| 同一天来两次 | **只打第一笔**。当天第一笔享受折扣，之后当天再消费原价 |
| 能跟优惠券一起用吗 | **不能**。达到次数时会员折扣优先，再输优惠券码会被拒 |
| 折扣能给别人用吗 | **不能**。折扣只能用在这位会员**本人的订单**上，不能转给朋友 |

| 后台把订单挂到会员名下 | **已结算的订单也能补挂**，但只记「这一单是他来的」：不退折扣、不补发奖励、不动已收金额。已经属于别的会员的订单不能改归属 |
